## Project Overview

A WebAR experience using MindAR + Three.js. When the device camera detects a 2D image target (`targets.mind`), a lotus bloom animation plays and a 3D Buddha model (`model_small.glb`) appears on top of the image.

## Running the project

Serve with any static file server on port 5500 (required for camera access via `localhost`):

```powershell
npx serve . -l 5500
# or use VS Code Live Server extension (defaults to port 5500)
```

Open `http://localhost:5500` in a browser. Camera permission is required.

## File structure

- `index.html` — entire app (single file, no build step)
- `targets.mind` — compiled AR image target (generated by MindAR compiler from a source image)
- `model.glb` — original 3D model (16MB, not used directly)
- `model_small.glb` — compressed model (1.5MB, used in production); regenerate with:
  ```powershell
  npx @gltf-transform/cli optimize model.glb model_small.glb --texture-compress webp
  ```
- `libs/` — local copies of CDN scripts to avoid slow network load:
  - `mindar-image-three.prod.js` — MindAR 1.2.5 (ES module, requires CDN importmap for chunk deps)
  - `three.module.js`, `GLTFLoader.js`, `OrbitControls.js`, `meshopt_decoder.module.js`
- `utils/BufferGeometryUtils.js` — dependency of `GLTFLoader.js` (relative import `../utils/`)

## Architecture

Everything lives in `index.html` as a single `<script type="module">`. The importmap at the top of `<head>` maps `three` and `three/addons/` to jsDelivr CDN; MindAR is imported directly from CDN because its chunk files (`controller-*.js`, `ui-*.js`) must be resolved relative to the CDN URL.

**Animation pipeline** (`bloom` variable drives everything):
- `bloom` goes 0 → 1 when target is found; resets to 0 on target lost
- Lotus petals: each petal pivot's `rotation.x` is driven by `eased(bloom, delay)` — inner layer opens first
- Gold particles: fade in at `bloom > 0.4`, loop indefinitely
- Buddha model: fades in at `bloom > 0.6`
- Point light intensity and orbit tied to `bloom` and time `t`

**Key dependency**: `model_small.glb` was compressed with meshopt, so `GLTFLoader` must have `MeshoptDecoder` set via `loader.setMeshoptDecoder(MeshoptDecoder)` or geometry will be invisible.

## Known constraints

- MindAR's prod build is an ES module with Rollup chunks — it cannot be loaded as a plain `<script>` tag; must use `type="module"`.
- `GLTFLoader.js` in `libs/` has a hardcoded relative import `../utils/BufferGeometryUtils.js`, so that file must exist at `utils/BufferGeometryUtils.js`.
- Camera only works on `localhost` or `https://` — plain `http://` on a remote host will fail silently.
